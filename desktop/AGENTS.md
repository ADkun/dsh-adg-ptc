# AGENTS.md — desktop（Windows 桌面操控 CLI）

`desktop/` 是一个**零依赖的 Windows 桌面操控 CLI**：看（截屏 / 窗口 / UIA 树）、查（物理坐标下是谁）、动（SendInput 合成输入 / 元素自带 UIA pattern 的语义操作）、复核（动作前后的可观测差异）。它是 `browser/` 的互补面 —— 浏览器管网页，它管本机桌面窗口。

**唯一入口**是 `cli.mjs`（零依赖，Node `>= 22`）；所有原生调用都在随模块发布的 `scripts/bridge.ps1` 里，Node 侧只用**文件重定向**捕获它的输出（受限令牌下 `spawn(..., {stdio:'pipe'})` 会 EPERM，见「红线」）。**Windows 专用**：非 Windows 上除了 `profile`（会如实打印 `WINDOWS_ONLY=false` + `WARN=`）之外每个命令都直接报错，不会假装能做。

装的落点是 `${DSH_HOME:-~/.dsh}/desktop/`（重跑 `install.*` 即生效，不用重启 dsh）。

## 命令

```sh
node cli.mjs help                       # 命令 / 选项的**唯一真相源**，本文件的表只是速查
node cli.mjs profile                    # 环境自检：Node / PowerShell / DPI / 屏幕 / 自身完整性级别
node cli.mjs screen [--out <png>] [--region <l,t,w,h>]   # 截屏，不缩放；默认整张虚拟屏
node cli.mjs windows                    # 枚举可见顶层窗口（进程 / 类名 / 矩形 / 完整性级别）
node cli.mjs uia [--hwnd <0x..>] [--depth N] [--name <子串>] [--id <el_id>] [--limit N]
node cli.mjs point --x <px> --y <px>    # WindowFromPoint 往返：这个物理坐标下是哪个窗口/元素
node cli.mjs click --x <px> --y <px> [--button left|right|middle] [--double] [--clicks N] [--force] [--raise] [--target-hwnd <0x..>]
node cli.mjs move  --x <px> --y <px> [--force]           # 只移指针，绝不点击
node cli.mjs type  --text <字符串> --hwnd <0x..> [--force] [--x <px> --y <px>]
node cli.mjs key   --keys <如 ctrl+s> --hwnd <0x..> [--force] [--x <px> --y <px>]
node cli.mjs scroll --x <px> --y <px> --dy <n> [--force] [--target-hwnd <0x..>]   # 正=上，负=下
# type/key 的 --hwnd 是**必填**（收键窗口；不指名就可能把字打进别的窗口），--x/--y 只指定观测作用域
node cli.mjs invoke --id <el_id> [--set-value <v>] [--fallback-point] [--force] \
                    [--hwnd <0x..>] [--name <子串>] [--depth N] [--limit N]   # --hwnd 强烈建议给
node cli.mjs verify [--x <px> --y <py>] [--expect k=v;k=v]  # 只观测，不注入
node cli.mjs probe                      # 只做内存编码的诊断：回显注入结构体的原始字节，**从不发事件**
node cli.mjs snapshot [--hwnd <0x..>] | [--x <px> --y <px>]   # 只读内容读数（独立子进程 + 零副作用：崩了也不拖垮注入）

# desktop/ 的单元测试（零依赖、不碰真实桌面；纯函数层）
cd desktop && node --test test
cd desktop && node --test --test-isolation=none test        # 沙箱里同样必须加这个 flag

```

常用开关：`--json`（末尾追加一行 `JSON=`）、`--dry-run`（只算坐标与归一化值，**不发事件**）、`--force`（跳过三处闸门：目标完整性级别更高、`GEO_MISMATCH` 几何矛盾、以及显式 `--target-hwnd` 与落点不符（`LANDING_PREFLIGHT=false`））、`--target-hwnd <0x..>`（坐标类命令：**显式**声明要操作哪个窗口；给了它 `LANDING_IN_TARGET` 才给布尔，不给就只报 `LANDING_SAME_WINDOW` 并把 `LANDING_IN_TARGET` 记成 `unknown`）、`--raise`（注入前 `SetWindowPos HWND_TOPMOST` 抬升目标窗口；**只对能指名窗口的命令有效** —— 鼠标类靠 `--x/--y`、键盘类靠 `--hwnd`，两者都没有时给一条 `WARN=` 且不发事件）、`--settle <ms>`（默认 150）、`--no-pixel`、`--no-content`（跳过内容快照那一次 spawn，省一整个子进程的时间）、`--timeout <ms>`（默认 60000）、`--hwnd <0x..>`（**`type` / `key` 必填**：键只会送到前台窗口，不指名就可能打进别的窗口；`uia` / `invoke` / `snapshot` 用它限定作用域）、`--name <子串>` / `--depth N` / `--limit N`（`uia` 与 `invoke` 共用；`--double` 的真实语义是**连发两次点击**（真机靶侧计数 +2、`EVENTS_MATCH_PLAN=true`），而"双击消息（`WM_LBUTTONDBLCLK` / UIA `DoubleClick`）会不会触发"**分两层看：OS 层已观测、控件框架那一层才是没观测到的** —— OS 层**确实投递** `WM_LBUTTONDBLCLK`（自建窗口过程、类样式 `CSTYLE=0xB` 含 `CS_DBLCLKS` ⇒ 靶侧日志 `DOWN / UP / DBLCLK / UP`；无该位 ⇒ 没有），**不充分的是控件框架** —— WinForms 的 `BUTTON` 类样式 `0x8B` 也含该位、窗口过程的原始日志里**有** `DBLCLK`，但托管事件只有 `CLICK n=1/n=2`、没有 `DBLCLK_EVENT`（`ControlStyles.StandardDoubleClick` 默认关）—— 别把它当双击语义的保证（以上真机读数来自**另一路完全权限会话的实测记载，非本会话验证**）。**`--limit` 是遍历预算**不是显示上限 —— 走到它就停并报 `TRUNCATED=true`，此时 `COUNT` 是"走到的元素数"，不是桌面上的元素总数）。**用不上的开关一律报用法错**（`checkFlagScope`，退出码 2），不许静默忽略 —— 真机踩过 `move --button right` 拿到普通移动、`type --x 5 --y 6` 悄悄丢掉坐标、拼错开关名（`--dryrun`）什么都不报。

输出契约是 `KEY=VALUE`（一行一个键），出错走 stderr 的 `ERROR=<msg>`。**完整用法与全部选项以 `node cli.mjs help` 当场输出为准**，本表不复制。

## 零依赖

`package.json` 只声明 `engines.node >= 22`、`"type": "module"`、`scripts.test = "node --test test"`，**没有 dependencies / devDependencies**。原生能力全部经 `scripts/bridge.ps1`（Windows PowerShell 5.1，`Add-Type` + P/Invoke 到 `user32.dll` / `kernel32.dll` / `UIAutomationClient`）与本机已有的 Node 标准库获得，不装任何东西。

`scripts/bridge.ps1` 必须 **ASCII-only 且无 BOM**（照 `notify/scripts/toast.ps1`）：Windows PowerShell 5.1 按系统 ANSI 代码页解无 BOM 脚本，非 ASCII 字节会让**引号配对失配**并报与真实原因无关的语法错。非 ASCII 只经 `-Text` / JSON 字符串字段传入。

## 红线

1. **注入类命令的成功判据是可观测差异，绝不是 `SendInput` 的返回值。** UIPI 拦下合成输入时 `SendInput` 照样返回"已插入 N 个事件"且 `GetLastError=0`，事件随后被静默丢弃。所以每条注入命令都打印 `CHANGED=true|false|unknown` + `BEFORE=`/`AFTER=`；坐标类命令另有硬件级回读 `CURSOR_AFTER=` / `CURSOR_LANDED=`。**三态里的 `unknown` 是必须的**：没有差异、而且这次动作的效果落在判据覆盖范围之外（没抓像素、也读不到任何 UIA 内容属性）时，报 `false` 会把真成功说成失败 —— 真机实测 `type` / `key` / `scroll` 都报过 `false` 而靶侧 `TextChanged` 日志、独立 UIA `ValuePattern` 读回、滚动条 UIA 读数三者一致证明动作已生效。**"我看不见这类动作的效果"绝不许报成 `false`。** 这条按命令落地（`INJECTION_CRITERIA` / I7f）：`scroll` 的效果**只有滚动位置读数**看得见（光标下元素自己，或它 3 层内祖先里带 `ScrollPattern` 的那个），`type` 只有 `Value`、`key` 有 `Value`/选中态/`Toggle`/`RangeValue`/滚动位置几类 —— 需要的这一类**一条都没读到**时一律 `CHANGED=unknown` + `WARN=`，读到且没变才轮得到 `false`。读到哪几类由 `CONTENT_KINDS=value=1,scroll=2,…` 逐类报出（**光看 `CONTENT_BEARING_COUNT=` 总数会误导**：`scroll` 要的是 `scroll` 那一类）。引导句也按命令分开写（`injectionWarn` 的 `kindTail`），不许让 `scroll` 显示"可能是坐标落空"这类误导句。**两条边界（真机实测）**：①`EVENTS_MATCH_PLAN=true` 与 `LANDING_IN_TARGET=true` 都**不是**"靶侧真的收到/点中了"的证据 —— 靶窗被置顶但没拿到前台时，`--double` 靶侧只 +1、`--clicks 3` 靶侧 +0，而这两行读数都是 `true`（切到前台后就复现不出来）；要证明生效只能看靶侧自己的计数/日志或 `--expect`。②动画期的窗口矩形是**过渡值**（实测抬窗瞬间读到 `0,0,260,51`）⇒ 抬窗/移动窗口后至少等 300–500 ms（`--settle`）再取坐标或操作。 来源：本机实测（受限令牌 Low 完整性级别下 `rc=1 err=0` 而指针纹丝不动）；载体：[真机] 在完全权限与受限两种会话里各跑一次 `click`，对比 `CHANGED` / `CURSOR_LANDED`（`testing-guide.md` 的注入闭环用例 `D52`/`D53`，被拦时的正确输出是 `D55`）。
2. **坐标一律是真实物理像素，进程启动即声明 `PER_MONITOR_AWARE_V2`。** 非 DPI 感知进程拿到的坐标被系统虚拟化（本机实测 1707×1067 vs 真实 2560×1600）；`SendInput` 用 `MOUSEEVENTF_ABSOLUTE|MOUSEEVENTF_VIRTUALDESK|MOUSEEVENTF_MOVE`（`0xC001`），归一化 `round((x - 虚拟屏原点) * 65535 / (尺寸 - 1))`，分母是**尺寸减一**、不是尺寸。**传给 Win32 API 的坐标必须先确认它要的是屏幕坐标还是客户区坐标**：`WindowFromPoint` 要屏幕坐标，而 `RealChildWindowFromPoint` 的 `pt` 是**接收窗口的客户区坐标**（点在该窗口客户区内且没压到子窗口 ⇒ 返回**这个窗口自己**，落在客户区外才返回 `0`，**与是不是顶层窗口无关** —— 真机实测，见 `design.md` I7g）；把屏幕坐标传给它只会得到"巧合正确"的指针。本模块曾这样调过它并留下一个 `leafHwnd` 字段，第十二轮核实**全仓无消费方**后把该调用与 P/Invoke 声明删除（`scripts/bridge.ps1` 96353 → 96321 字节，无可观测行为变化）。这次删除现由机器守卫钉住：`test/content-safety.test.mjs` 断言剥掉注释后 `bridge.ps1` 不许再含 `RealChildWindowFromPoint` / `leafHwnd`（注释里允许，`Invoke-PointCommand` 里那段 `NOTE: RealChildWindowFromPoint() …` 注释是刻意留的），`cli.mjs` 与 `lib/*.mjs` 连注释里也不许含。载体：[机检] `node --test test` 的坐标换算用例（含负原点与 150% 缩放）+ `test/injection.test.mjs` 断言 `dwFlags == 0xc001` + [真机] `screen` 的 `WIDTH/HEIGHT` 等于物理像素。
3. **目标完整性级别高于自身时，在注入前就阻断**，`ERROR=UIPI blocked: target integrity level higher than ours`，不许静默继续。要硬发必须显式 `--force`（会多打一条 `WARN=`）。级别读不到时按 `block-integrity-unknown` 处理，不假设它比我们低。载体：[机检] `decideInjection` 的单测；[真机] 受限会话里对 Medium 窗口跑 `click`。
4. **`invoke --id` 只用元素自带的 UIA pattern，不支持就报错，不许猜、不许自动退化成坐标点击。** 退化只在显式给 `--fallback-point` 时发生，并且会打 `WARN=` 说明"这不是语义操作"。载体：[机检] `chooseAction` 单测；[真机] 对无 pattern 的容器元素跑 `invoke --id`，期望退出码 2。
5. **安全边界（明文不做）**：不绕 UAC、不碰安全桌面（Winlogon / UAC 同意界面）、不做进程注入、不改系统设置、不驱动管理员权限进程。本工具只**读**窗口与 UI 状态 + 用 `SendInput` 合成输入。出处是本文档「职责与边界」一节里逐条列出的"不负责"（`design.md`）；载体：[评] 人工 review 改动是否新增越界系统调用。
6. **`scripts/bridge.ps1` 保持 ASCII-only 无 BOM。** 载体：[机检] `node -e "import('node:fs').then(f=>{const b=f.readFileSync('scripts/bridge.ps1');console.log(b[0].toString(16), b.every(c=>c<128))})"` ⇒ `23 true`（**必须用 ESM 写法**：本包 `"type": "module"`，`require` 会抛 `ERR_REQUIRE_ESM`）。
7. **注入结构体的字段偏移只有一个真相源（C# 的 `InputLayout` 常量），事件一律由 C# 工厂方法构造。** 两处历史缺陷都是"赋值看着完全正确、字节却是错的"，且 `SendInput` 照样报"已插入 N 个事件"：①把成员嵌在 union 里逐成员赋值（PowerShell 对值类型的嵌套成员拿到副本，整块结构零送出）；②平铺后**键盘**的 `dwFlags` 放错偏移（`WinUser.h` 里 union 起点是 8，`MOUSEINPUT.dwFlags` 在 **20** 而 `KEYBDINPUT.dwFlags` 在 **12** —— 共用一个字段名就把 `KEYEVENTF_UNICODE` 静默清零，真机实测 `type --text ABCDEFGHIJ` 报 `INSERTED_EVENTS=20 CHARACTERS=10 CHANGED=false` 而靶窗口一个字符都没进）。**PowerShell 侧不许写任何结构体字段**（只做像素归一化与 `[uint32]` 装箱）。载体：[机检] `node cli.mjs probe` 的 `MOUSE_MATCHES_CANONICAL` / `KEY_MATCHES_CANONICAL` / `KEY_UP_MATCHES_CANONICAL` / `WHEEL_MATCHES_CANONICAL` 必须全 `true`（与 `WinUser.h` 原样的嵌套 union 参照结构体逐字节比对）+ `test/injection.test.mjs` 钉死 12 个 `OFFSET_*` 与三个 size 常量；[真机] 改了这条路径必须在**完全权限**会话里重跑 `type` / `key` 的注入闭环（键盘要能被 UIA 独立读回）。
8. **滚轮的 `mouseData` 是 uint32 位模式，负数要先转位再装箱。** `--dy -3` ⇒ `-360` ⇒ `0xFFFFFE98`；把 `-360` 直接交给 `[uint32]` 参数会让整条命令在造事件之前死掉（真机实测 `Cannot convert value "-360" to type "System.UInt32"`，向下滚轮永远 exit 1）。载体：[机检] `test/injection.test.mjs` 的滚轮用例（`WHEEL_DW_DATA=-360` 且同一批字节按 int32 读回是 `-360`）；[真机] `testing-guide.md` 的未观测项（读 `VerticalScroll.Value` 前后差）。
9. **UIA 元素的 `patterns` 必须是字符串数组，桥侧只许有一处包装。** `Get-PatternNames` 用 `return ,@($names)` 保住"单元素也当数组"，调用点用 `[object[]](Get-PatternNames …)`，**不许再加 `@()`**（两层叠起来得到 `{"patterns":[["InvokePattern"]]}`）；去掉逗号则空数组会写成 `{"patterns":null}`。坏形状被 `patternList()` 归一化成空列表后与"这个元素不支持语义操作"**完全同形** ⇒ 所以另设 `patternShapeProblem()`，`uia` / `point` / `invoke` 三条路径都要打 `WARN=patterns 形状异常：…`，不许让兜底函数把真缺陷掩盖过去。载体：[机检] `test/patterns-shape.test.mjs`（原始 JSON 里不许出现字面 `"patterns":[[`；同一元素在 `uia --depth` 与 `uia --id` 两条路径下 `deepEqual`）；[真机] `uia --depth` 里 `Window` 元素的 patterns 列显示 `WindowPattern` 而不是 `-`。
10. **`--dry-run` 的计划与实际注入必须同源。** dry-run 由桥用 `-PlanOnly` 走**同一条构造路径**算（只构造、不发送），真跑时报 `EVENTS_MATCH_PLAN=`（`INSERTED_EVENTS` 是否等于 `EXPECTED_EVENTS`）。来源：`click --double --force` 真机报 `INSERTED_EVENTS=3 CLICKS=1` 而 dry-run 自报 `CLICKS=2 EXPECTED_EVENTS=5` —— 各算各的计划就是假证据。同一处改动暴露了 `move` 也会 append 一对 down/up（"移动指针"变成一次点击，`$Button` 默认 `left`），所以 `move` 现在显式走 `-MoveOnly`，`BUTTON=` 为空、`CLICKS=0`、`EXPECTED_EVENTS=1`。载体：[机检] `test/plan.test.mjs`（7 条注入命令各钉一个期望值；dry-run 不许出现 `INSERTED_EVENTS` / `EVENTS_MATCH_PLAN`）。
11. **元素 id 与快照作用域绑定，截断不许说成"不存在"。** `el_…` 只在取它的那次遍历里稳定；桌面一拥挤，从桌面根做的遍历会在 `--limit` 处停下并报 `TRUNCATED=true`。真机实测：11/11 次 `invoke --id` 失败，原因就是 id 取自被截断的根快照，而报的是"元素可能已消失"。所以 `invoke` 有 `--hwnd` / `--name` / `--depth` / `--limit`，并把 `SNAPSHOT_SCOPE=` / `SNAPSHOT_COUNT=` / `SNAPSHOT_BUDGET=` / `SNAPSHOT_TRUNCATED=` 全打出来；截断时找不到 id 报的是**截断**，并叫人加 `--hwnd` 后用同一作用域重新取 id。`pickElement` 的 `reason` 里不许出现"元素可能已消失"这种结论（三种原因都要留活口）。载体：[机检] `test/plan.test.mjs` 的截断用例 + `snapshotScopeText` 单测。
12. **内容类判据不许静默缺席。** `verify` / 注入命令的复核会把 UIA 内容快照的可读条数打出来（`CONTENT_BEARING_COUNT=`），一条都读不到时 `contentNote` 里必须留原始异常文本（受限令牌下典型是 `Access is denied`），**不许把读不到当作"没有变化"**。内容读数还必须是**独立子进程**（`snapshot`）读的，并且打出 `CONTENT_PROBE=ok|failed|skipped`（`skipped` ＝ 调用方给了 `--no-content`、探针没跑，此时还要多打一条说明覆盖面的 `WARN=`，**不许写成 `ok`**）：探针崩掉时这一类判据记 `unknown`（`contentBearingCount` 归 0、`contentNote` 留崩溃原文），**像素哈希在也不许改报 `false`** —— 像素看不见"文本框里的字变了"；反过来，探针崩掉时"后一次读到空串"也不能算成"界面变了"（`compareStates` 会让内容这一类整个退出差异集合）。载体：[机检] `changeVerdict` / `compareStates` / `applyContentSnapshot` 单测（三种情形 + 崩溃注入）；[真机] 受限会话里 `type` 报 `CHANGED=unknown` + `WARN=`，完全权限会话里报 `true`。
13. **UIA 的 range 文本方法能抛 AV，`try/catch` 抓不住 —— 这类调用一律不许进 `bridge.ps1`。** `TextPattern.GetSelection()[0].GetText(-1)` 会抛 `System.AccessViolationException`（`RawTextRange_GetText` → `TextPatternRange.GetText(Int32)`）；AV 是 corrupted-state 异常，参数求值时就炸掉整个进程、`catch` 一行都不执行，Node 侧只看到 `ERROR=bridge 没写出结果文件（exit=3221225477）`（`0xC0000005 = STATUS_ACCESS_VIOLATION`）—— 真机上它让六条命令全部在取前态时就死。**任何暴露 `TextPattern` 的 WinForms 文本框都中，空的也中**（`len=0` 照样崩），而同一元素上 `DocumentRange.GetText(-1)` 正常（实测 `DOC_OK len=409`），所以"换成正的 `maxLength`"不成立。因此：①`Read-ElementContent` 只许 `TryGetCurrentPattern` 取 pattern + 读 `Current.*` **属性**，源码里有 ASCII 的 POLICY 注释锁住（文本选区那条读数已被整个删掉，`ValuePattern` 的 `value` 覆盖同样的语义）；②内容探针单列 `snapshot` 子命令、跑在独立子进程里，Node 侧用容错通道 `probeBridge` 调（崩溃 / 超时 / 无输出都映射成 `{ok:false, exitCode, crashed, crash}`，绝不抛）；③`exit 3221225477` 要在错误里被认出来（`crashExitName`：`STATUS_ACCESS_VIOLATION (0xC0000005)`）；④排查同类问题时记牢 **Windows PowerShell 里 `exit 3221225477` 会被 `[int]` 溢出成退出码 0**，要复现这个码得写 `exit -1073741819`。载体：[机检] `test/content-safety.test.mjs` —— 剥掉注释行后 `bridge.ps1` 里 `GetText(` / `GetSelection(` / `GetBoundingRectangles(` / `DocumentRange` **一个都不许有**；`Invoke-VerifyCommand` 不许含 `Get-ContentSnapshot`、`Invoke-SnapshotCommand` 必须含它且不许含 `Send-Inputs`/`SetForegroundWindow`/`Raise-Window`/`AttachThreadInput`；对 `test/fixtures/dying-bridge.ps1`（`exit -1073741819`）断言容错通道给出 `{ok:false, exitCode:3221225477, crashed:true}`；`node cli.mjs snapshot` 自己不许崩（退出码 ≠ `3221225477`）。[真机] 完全权限会话里六条命令都跑到"注入 + 打印结论"。详见 `design.md` 的 I7e 与 `testing-guide.md` 的「已知平台坑」（含 15 行最小复现）。
14. **坐标类命令在注入前必须做几何自洽检查，矛盾时默认不发事件。** `GEO_WINDOW_RECT=`（`GetWindowRect`）与 `GEO_UIA_ROOT_RECT=`（同一顶层窗口的 UIA 根矩形）逐边比对（容差 2 px），再加上"请求点上的 UIA 元素自身矩形是否包含该点"，合成 `GEO_MISMATCH=true|false|unknown`；`true` 时**默认 `UsageError` + 退出码 2**（要照原样点必须显式 `--force`，并保留那条 `WARN=`）。三态的边界是**"缺测绝不许读成一致"**：`false` 只在两条读数都取到且都印证时才给，**任一条缺失 ⇒ `unknown`**（只拿到一条也一样）+ 一条 `WARN=` 说明不能当成"几何一致"；唯一例外是 `uia --hwnd` 这一路本来就没有查询点（`requirePoint: false`），它只验根矩形并在 `reasons` 里写明这一点。来源：真机踩过 —— 靶窗口最大化时 `windows` 与 `uia` 给出两套互不相容的矩形，照 `uia` 那组算出的坐标在 `point` 里解析成**另一个控件**（点击打空而人以为点对了）。载体：[机检] `geoVerdict` / `rectsAgree` / `rectContains` 单测 + `point` 与 `click --dry-run` 的 `GEO_*` 四行；[真机] 完全权限会话里最大化靶窗口后跑 `point`，看是否 `GEO_MISMATCH=true`（本机受限会话里 `FromPoint` 被拒，只验到两套根矩形一致 ⇒ 这条真机面**未观测**，量法见 `design.md` I2b 与 `testing-guide.md`）。
15. **"落点在目标内"必须先有显式目标 —— 没给 `--target-hwnd` 时不许给布尔。** 没有显式目标就只报 `LANDING_SAME_WINDOW=true|false`（落点像素上的顶层窗口与这次认定的目标是不是同一个）并把 `LANDING_IN_TARGET=unknown` + `WARN=`；给了 `--target-hwnd` 才给 `LANDING_IN_TARGET=true|false`（并打 `TARGET_SOURCE=--target-hwnd`、`TARGET_HWND=`、`TARGET_ROOT_HWND=`、`TARGET_IN_WINDOW_LIST=`）。来源：真机实测 —— 前台是 A、故意点隔壁 B 的按钮，输出照样是"在目标内=true"，靶 B 计数 +1、靶 A 日志无新行 ⇒ 那一行只证明"落点像素上还是同一个窗口"，与"点进了我想要的窗口"无关，极易被当成功证据。`--dry-run` 里这一行给 `not-evaluated`（没发事件，落点归属无从评估）。载体：[机检] `landingNote` 的 `explicitTarget` 两条路径单测 + `click --dry-run --target-hwnd 0x…` 的 `TARGET_SOURCE=--target-hwnd`。**而且这道判据要真的拦住错误的目标（第十轮新增）：显式给了 `--target-hwnd` 时，落点归属在注入前先闸一道**（`LANDING_PREFLIGHT=true|false|unknown`，三态口径与红线 14 的几何闸门**同款**）：`false` ⇒ 默认 `UsageError` + 退出码 2、输出里**没有** `INSERTED_EVENTS=`（要照原样点必须显式 `--force`，那段文字随即变 `WARN=`）；`unknown` ⇒ 只 `WARN=`；`true` ⇒ 放行；没给显式目标时行为不变。来源：真机实测 —— 调用方给了 `--target-hwnd` 而落点被别的窗口占住，CLI 只打了 `LANDING_IN_TARGET=false` 就照样把事件发了出去（更早还有约 40 次单击落到用户终端上的记录）。**它是"发事件前"的门，事后那行 `LANDING_IN_TARGET=` 是"发完之后的记录"，两道都要看**（探针与注入之间还有竞态）。载体：[机检] `landingPreflight` 单测 + `test/cli-contract.test.mjs`；[真机] `--target-hwnd` 指隔壁窗口 ⇒ 默认拒发、加 `--force` ⇒ 放行且保留 WARN。

16. **收键窗口必须是显式给的那个，`type` / `key` 的 `--hwnd` 不许变成可选。** 键只会送到前台窗口，而 Windows 拒绝后台进程抢前台 —— 不给目标时桥会把字符发给"当时的前台窗口"。真机实测一次 `type --text ABCDEFGHIJ` 在靶窗没抢到前台时，10 个字符进了别的窗口（疑似用户终端）、靶侧日志零变化、CLI 只报 `CHANGED=unknown`。给了 `--hwnd` 之后整条路才成立：桥用同一个值当 `focusTarget`（`$keyboardFocusSource` 是"发给谁"的**单一来源**，plan 与真跑同源）、`--raise` 抬的就是它、前台闸门（`Focus-WindowForKeyboard`）按它判定，重试后仍非前台 ⇒ 报错且**一个键都不发**。缺 `--hwnd` ⇒ 用法错、退出码 **2**（`requireKeyboardHwnd`）。载体：[机检] `test/cli-contract.test.mjs`（缺 `--hwnd` ⇒ 2 且报错点明"键只会发给前台窗口"）+ `test/params-map.test.mjs`（CLI 的 `params` 里必须有 `Hwnd`、桥侧必须有 `$keyboardFocusSource`）+ `test/plan.test.mjs` 的 `PLAN_FOCUS_SOURCE=hwnd`；[真机] 先让别的窗口占前台再 `type --hwnd <目标>`，期望"报错而非发键"。
17. **内容探针的作用域是加法的，不许互斥。** `--hwnd` 钉根、`--x/--y` 加读落点与它 3 层内的祖先，**两个都给就都读**，实际用了哪个由 `CONTENT_SOURCE=` / `SNAPSHOT_SOURCE=`（`foreground` / `hwnd` / `point` / `point+hwnd`）摆在明面上。来源：真机 `scroll --x 1620 --y 480 --dy -5` 靶侧 `WPF_SCROLL v=48 → 96` 证明滚了，而复核快照里 `CONTENT_KINDS` 全 0；根因是 `captureState` 与 `Invoke-SnapshotCommand` 两处 `if/elseif` —— 根一旦拿得到（`verify` 总会填 `contentRoot`），坐标就永远不再下发，`point`/`ancestor`/`scroll` 那几类读数结构性消失，I7f 要的那一类永远凑不齐。载体：[机检] `test/params-map.test.mjs`（`captureState` 必须同时下发 `Hwnd`+`X`+`Y`，且源码里不许再出现 `else if (args.x !== undefined`）；[真机] `verify --x …` 打 `CONTENT_SOURCE=point+hwnd`（修前只会是 `hwnd`）。
18. **CLI→桥 的参数映射是契约：`params` 就是全部输入，漏传一个键没有任何运行期信号。** 桥用 `param()` 显式绑定（`-File`），所以**键名写错会当场报绑定错误**，而**"压根没写"完全静默** —— I7h / I7i 两个真机缺陷都属于后者。改任何命令的 `params` 都要同步 `test/params-map.test.mjs`（它冻结桥的 25 个参数名 —— 新增的 `ElRuntimeId` 见红线 22 —— 外加逐命令核对函数体里必须出现的键）；`--dry-run` 的 `PLAN_FOCUS_SOURCE=` / `PLAN_HWND=` 回显是"参数到底有没有传下去"唯一不用发事件就能取的判据。完整映射表见 `design.md` 的 I10c。

19. **组合键里的单字符不许走 `KEYEVENTF_UNICODE`（组合键必须"真按住修饰键"）。** `flags=4` 注入的是**字符**、绕过修饰键状态：真机 `key --keys ctrl+a --hwnd <靶>` 靶侧只多了一个 `a`（随后 `type --text V` 是**追加** ⇒ 全选从未发生），而 CLI 侧 `INSERTED_EVENTS=4 EVENTS_MATCH_PLAN=true` 一切正常 —— 这类缺陷只能在靶侧或 plan 里看出来。规矩：`$hasModifier` 算**一次**当唯一真相源；含修饰键的组里单字符经 `Get-CharVirtualKey`（a-z 用码减 32、标点走 `VkKeyScan`）换成 `VK_*` 且 `flags=0`；无修饰键的单字符保留 Unicode 直送；`key A` 保留大小写（修前被小写化）；未知键名 `Fail`（退出码 1）而不是静默变空事件。判据是 `--dry-run` 的逐键 `PLAN_KEY <i> | <name> | PHASE= | PATH= | VK= | SCAN= | FLAGS=`（I7k；顺序见红线 20）。载体：[机检] `test/key-chord.test.mjs`（运行时 7 组 + 静态守卫；另有"不可映射字符 fail-closed"与"`$named` 表 ↔ 报错文案同步"两条）；[真机] `ctrl+a` 是否真变成全选 —— **未观测**，量法见 `design.md` I7j。

20. **组合键的发射顺序：修饰键全部按下 → 载荷键 down/up → 修饰键反向抬起。** 只把描述符修对是不够的 —— 真机复验（修完红线 19 之后）仍然不通过，因为旧分支"每个描述符各发一对 down+up"把 `ctrl+a` 发成了 `ctrl↓ ctrl↑ a↓ a↑`：修饰键被点一下就松开，主键单独按下。靶侧三份证据：`ctrl+a` ⇒ `[HELLO]`→`[HELLOa]`（一个小写 `a`），随后 `type --text V` ⇒ `[HELLOaV]`（**追加**）；`ctrl+c` ⇒ `[HELLOaVc]`；`shift+a` ⇒ `[HELLOaVca]`（**小写**）。而 CLI 侧这三条全是 `EXPECTED_EVENTS=4 INSERTED_EVENTS=4 EVENTS_MATCH_PLAN=true` —— **事件数完全看不出顺序**，所以判据只能是 `PHASE=` 列（`modifier-down|key-down|key-up|modifier-up`）。顺序在 `ConvertTo-KeySequence` 里一次算好（plan 与真跑同源），注入循环按 `phase` 决定 `-Up`；修饰键抬起取**逆序**；无修饰键时退化为原来的逐键 down/up（行为不变）。载体：[机检] `test/key-chord.test.mjs`（`ctrl+a` / `ctrl+shift+a` / `shift+a` 的 `PHASE` 序列、抬起逆序、`EXPECTED_EVENTS == plan.length`；静态守卫：`ConvertTo-KeySequence` 必须在、"注入按 phase 决定 Up"必须在、"每描述符一对 down+up"的老形状不许回来）；[真机] `ctrl+a` / `ctrl+c` / `shift+a` 是否真成立 —— **未观测**，量法见 `design.md` I7l。

21. **"`GetRuntimeId()` 读不到"的元素不许在未限定窗口时当 `--id` 动手（`el_unknown` 是折叠 id，不是身份）。** 凡是读不到 runtimeId 的节点都被折叠成同一个 `el_unknown`，而 `pickElement` 的命中数闸门数的是**定位快照**那一份数组 —— 里面**恰好一个** `el_unknown` 就能放行，桥的第二遍遍历却取**第一个** `el_unknown`（不必是同一个元素；不给 `--hwnd` 时甚至可以不在同一个窗口），**不需要任何竞态**。所以形状闸门与 `uia` / `point` 的输出**都不变**（它必须继续看得见，藏起来就等于说"元素不存在"，触犯红线 11），但 `invoke --id el_unknown` **必须**显式给 `--hwnd`，否则 `UsageError` + 退出码 **2**，错误文本要说清"占位、不唯一、必须限定窗口"（不是"元素不存在"）。限定窗口后它仍没有身份可复核 ⇒ 走红线 22 的 `absent` 一路。载体：[机检] `test/pure.test.mjs`（`PLACEHOLDER_ELEMENT_ID` / `isPlaceholderElementId`）+ `test/cli-contract.test.mjs`（`invoke --id el_unknown` ⇒ 2）。

22. **元素身份随 `invoke` 一起下发，对不上就一步都不动（`ElRuntimeId`）。** 数命中数发生在**调用方的定位快照**上，动手却发生在桥的**第二遍遍历**里，两者之间只传了一个哈希（`ElId`）—— id 命中**不证明**是同一个元素（红线 21 是它的极端例子）。所以桥多一个**可选**参数 `ElRuntimeId`：给了就在**动手路径的任何动作原语之前**比 `runtimeId`（口径**不是**"文件里第一个 `TryGetCurrentPattern` 之前"：快照期 `Get-PatternNames` 就已经只读枚举过 pattern，那是清点、不是动作），不等 ⇒ `invoked=false` + `identityMismatch=true` + `patternError='element identity mismatch: id matched but runtimeId differs'` 并**立即返回**（一个 pattern 都没取、一个动作都没执行）。CLI 把定位快照的 `runtimeId` 原样下发；快照没有就**不下发**（不许凭空造），打 `ID_IDENTITY=absent` + 一条 `WARN=` 把缺口摆在明面上；`ID_IDENTITY=` 是三态 `checked` / `absent` / `mismatch`。**`mismatch` ⇒ 退出码 2（拒绝动手）**，与"动作没生效"的 **1** 分开：前者要重新取 id，后者要去查闸门与靶侧。缺省空串 ⇒ **老调用方式行为完全不变**。不许用"掺世代号 / 祖先链指纹"的办法绕：那会推翻 I6 的跨快照稳定承诺。载体：[机检] `test/element-identity.test.mjs`（假桥两次遍历报不同 runtimeId ⇒ 2 且 `OK=false`；判定与假桥都 dot-source `scripts/identity.ps1` —— **同一份**判定的唯一实现，改坏它红的是会执行的那条用例）+ `test/params-map.test.mjs`（冻结清单含 `ElRuntimeId`、闸门接线与位置在动手路径的任何动作原语之前；**这只证明源码文本层面的位置关系，不是"会执行"的证明** —— 把闸门调用与拒绝块一起包进恒假分支、或把这一整段套进 `& { … }` 子作用域，两个测试文件都仍然全绿（**实测形状非穷举**），见 `testing-guide.md` 的 D106 / D108）。

模块其余不变量（I1…I11、I2b、I6b–I6f、I7b–I7l、I9b、I10b–I10d）在 `design.md`；对抗性验证用例与"未观测"项在 `testing-guide.md`。

## 生效方式

`desktop/` 是**用户根下的普通文件**，不是 preset 也不是插件：改完重跑一次 `install.ps1` / `install.sh` 就生效，**不用重启 dsh**（`install.*` 的「2c. desktop/ 工具链」段先删后拷整个目录）。

```sh
node "${DSH_HOME:-~/.dsh}/desktop/cli.mjs" profile      # 复核装没装、DPI 与屏幕读数对不对
```

**但"改生效"不等于"能驱动窗口"**：要真正驱动普通用户窗口，**调用它的那一次会话必须是完全权限**（`danger-full-access`）。受限会话（`workspace-write` 等）的令牌是 Low 完整性级别，普通窗口是 Medium/High，UIPI 会拦下合成输入且是**静默**丢弃 —— 这时正确的输出就是 `CHANGED=false` + `WARN=`，不要为了"跑通"去掉闸门。完全权限解的是**降权**、不是获得管理员权限（实测：令牌 `S-1-16-8192` = Medium、`TokenRestrictedSids` 空、`TokenElevationType=3`/`TokenElevation=0`、Administrators 仍 deny-only、无 `SeDebug`），High 完整性级别的管理员窗口与 UAC 安全桌面依旧够不着。
