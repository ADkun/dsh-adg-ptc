# Task Queue — 治理域入口

一个演示用的最小治理域（adg-doc-criterion 的满分样张）：一个内存任务队列模块 queue，配一份当前真相（design）与一份未来意图（roadmap）。照着这套结构写，就能通过机检与对抗评审。仓库里文件在哪、改一处读哪份这类导航由 aoci 索引承担，本文件不列文件清单。

## 命令

```sh
npm test          # 跑 queue 的单测
node check-docs.mjs .   # 机检本治理域文档（adg-doc-criterion 自带脚本）
```

## 关键红线

1. 任务只能经 queue.enqueue() 入队，禁止直接改内部数组 —— 来源：评审决定（防越权改状态）。
2. 文档引用一律用「文件 + 符号名」作锚，禁止写行号 —— 行号是派生坐标，一改就静默指错。

## Quality Gates

| 检查项 | 载体 | 期望结果 |
|---|---|---|
| 文档机检 | [机检] node check-docs.mjs . | exit 0 |
| 认知索引 | [机检] aoci check | exit 0（每文件一条条目、无 stale） |
| 红线与理由抽查 | [评] 对抗评审子智能体 | 无 FAIL 项 |

**能力的边界**：机检证明不了文档与代码一致；每条判据须能追到对应测试或评审。
